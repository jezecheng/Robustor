# 知识点 × 方法论 错题诊断框架

> 状态：设计稿，尚未实现。日期：2026-11-26。
> 适用范围：`apps/api` 的标签模型与诊断流程；实现前需先完成文末「落地顺序」中的 P0。

## 1. 核心主张

错题诊断不是给题目堆标签，而是**在两张图上做最近失败节点定位**：

- 知识图回答「缺哪块知识」；
- 方法图回答「哪一步方法没想到、用错了，或前置方法没搭上」。

具体做法：用标准解生成「期望方法链」，用学生过程生成「实际方法链」，做序列对齐找出第一个偏离点，再把偏离点映射回两张图做前置闭包检查。整个流程分三阶段：**定位 → 归因 → 处方**。

```
输入证据（考点标注 / 标准解方法链 / 学生过程） 
      → ① 定位：考点 + 期望方法链
      → ② 归因：对齐步骤，定位断点
      → ③ 处方：前置闭包 → 补学路径
      → 单题诊断报告（主因 + 次因 + 证据 + 路径 + 验证题）
```

## 2. 三层结构

| 层 | 承担的问题 | 当前状态 |
|---|---|---|
| L1 知识层 | 这个考点依赖哪些更基础的知识？断在哪个前置？ | 已有：导入 4221 个知识点、6681 条 hard/soft 先修边（11 学科） |
| L2 方法层 | 这道题该用哪个方法？方法本身还依赖什么？ | 只有壳：20 个扁平方法标签，无学科、无依赖、无适用条件 |
| L3 证据层 | 学生实际做到了哪一步？ | 缺：`problem` / `solution` / `mark` 目前没有真实数据 |

## 3. 方法节点必须做成「可判定的节点」

现有 `Tag(type="method")` 只有一个名字，模型无法判断「该不该用、用得对不对」。每个方法节点需要 6 个字段：

| 字段 | 作用 | 例：倍长中线法 |
|---|---|---|
| `aliases` | 学生/老师的不同叫法 | 中线倍长、倍长类中线 |
| `applies_when` | 适用条件，必须可判定、能写反例 | 题面出现中线/中点，且需要转移线段或造等量关系 |
| `steps` | 2–5 步骨架，用于和学生过程对齐 | 延长 AD 至 E 使 DE=AD → 连 BE → 证全等 → 转移边角 |
| `prereq_methods` | 前置方法（方法链） | 构造全等三角形、SAS 判定 |
| `prereq_knowledge` | 依赖知识点 | 三角形中线、全等三角形判定、对顶角 |
| `misuse` | 典型误用，用于条件校验 | 只倍长不连线；把角平分线当中线套用；用 SSA 判全等 |

没有 `applies_when`，就只能做「方法缺失」判断，做不了「方法误用」——这是方法层最容易漏掉的一半。

## 4. 诊断主算法（有过程证据时）

1. **取考点**：`ProblemTag` 中 `weight >= 0.6` 的知识点作为本题考点集。
2. **期望链 M(p)**：从参考答案/解析抽有序方法序列 `[m1, m2, m3]`，而不是无序集合。
3. **实际链 M(s)**：从学生作答步骤抽；抽不出就留空（留空本身就是 `M-ABSENT` 的证据）。
4. **序列对齐**：`M(s)` 与 `M(p)` 做编辑距离对齐，取第一个偏离位 `i*`。
5. **归因**：对 `i*` 对应节点做两件事——查适用条件、查前置闭包，然后按下面的顺序判定。

判定顺序（防止「所有错题都归因知识缺失」）：

```
P-SLIP → M-MISUSE → M-ABSENT → M-BROKEN → K-MISSING / K-CONFUSE → UNKNOWN
```

先排掉最便宜、最确定的（抄错、算错），再往上走；全都对不上就输出 `UNKNOWN`，不硬编理由。

## 5. 归因码表

| 码 | 判据 | 典型表现 | 处方方向 |
|---|---|---|---|
| `P-SLIP` | 方法链与标准解一致，仅末步数值/单位/抄写出错 | 思路对、算错数 | 不补知识，练检查清单 |
| `M-MISUSE` | 调用了方法，但 `applies_when` 不成立 | 用 SSA 判全等 | 条件清单 + 反例题 |
| `M-ABSENT` | 实际链里完全没有该方法特征步骤 | 看到中点却没倍长 | 方法示范 + 识别训练 |
| `M-BROKEN` | 调用了 m，但 m 的前置方法 m0 缺失 | 想倍长，却不会构造全等 | 从 m0 补起 |
| `K-MISSING` | 方法依赖的前置知识点在近期题中从未正确使用 | 不知道中线平分面积 | 补知识点 + 2 题 |
| `K-CONFUSE` | 错误集中在相似概念的边界题 | 周长/面积、判别式/根 | 对比辨析 + 易混题 |

`M-BROKEN` 是方法层最典型的形态：倍长中线法依赖「构造全等三角形」，学生的问题往往不是没学过倍长，而是前置的构造没搭上。

## 6. 防过诊：单题疑似 / 题目簇确认

| 层级 | 规则 | 输出 |
|---|---|---|
| 单题 | 任一码命中 | `status=pending`，「疑似」，置信度 ≤ 0.6 |
| 题目簇 | 近 5 题内同方法/同知识点出现 ≥ 2 次同码 | 升级 `confirmed` |
| 解除 | 同标签连续 3 题独立正确 | 撤销该结论 |
| 冲突 | 同一方法出现两种码 | 两条都保留，按证据强度排序 |

## 7. 输出契约

```json
{
  "problem_id": "p_1a2b",
  "primary": {"code": "M-BROKEN", "tag": "倍长中线法", "confidence": 0.82},
  "secondary": [{"code": "K-MISSING", "tag": "三角形中线", "confidence": 0.61}],
  "evidence": [
    {"type": "step", "ref": "solution_step#3", "note": "只连了 BD，没有延长中线"}
  ],
  "path": [
    {"order": 1, "kind": "method", "target": "构造全等三角形"},
    {"order": 2, "kind": "method", "target": "倍长中线法"}
  ],
  "verify": {"tag": "倍长中线法", "count": 2, "pass": "2/2 独立完成"},
  "status": "pending"
}
```

硬性要求：**每条结论必须带 `evidence` 引用**。没有证据的归因不允许入库，否则整个框架退化成「AI 随口分析」。

## 8. 数据模型改动

| 改动 | 具体内容 |
|---|---|
| `TagEdge` 扩展 | 加 `relation`（`prerequisite` / `method_prereq` / `applies_to` / `alternative`）、`source`、`status`；唯一键改为 `(from, to, relation)`；现有 6681 条回填 `relation=prerequisite, source=taxonomy` |
| `Tag` 扩展 | 加 `method_json`（存 `applies_when` / `steps` / `misuse` / `signals`）；method 标签补 `subject` / `grade` |
| `ProblemTag` 扩展 | 加 `role`（`tested` / `expected_method` / `prerequisite`），区分「本题考点」与「解题所用方法」 |
| 新表 `SolutionStep` | `solution_id, seq, latex, method_tag_id, verdict`——现在 `Solution` 只有整段 latex，无法定位断点 |
| 新表 `Diagnosis` | `problem_id, primary_code, primary_tag_id, secondary_json, evidence_json, path_json, confidence, status, model, created_at` |
| 新表 `TagMastery` | `tag_id, score, evidence_count, updated_at`。**不要复用 `Tag.mastery_json`**，它是挂在标签上的全局字段，没有学生维度 |

## 9. 降级策略

| 情形 | 行为 |
|---|---|
| 方法层为空（当前状态） | 只输出 `P-SLIP` / `K-MISSING` / `K-CONFUSE` + 知识闭包路径，报告标注「方法维度未覆盖」 |
| 只有对错、没有步骤 | 只输出候选排序，置信度 ≤ 0.5，标「疑似」，不写入学情 |
| 学生用了另一种正确解法但算错 | 必须按**学生链**判定，否则会误判成 `M-ABSENT` |

## 10. 落地顺序

| 阶段 | 交付 | 出口条件 |
|---|---|---|
| P0 | 数据契约（第 8 节 6 项）+ 方法词表 20 → 80–120 条，人工审核 | 每个方法节点 6 字段齐全 |
| P1 | 知识-only 诊断 + 单题报告 | 不依赖方法层也能出结论 |
| P2 | 方法链抽取（参考答案/订正/模型自解三源）→ pending 方法标注 | 抽链准确率抽检 ≥ 80% |
| P3 | 条件校验 + 补学路径 + 验证题 | 路径长度 ≤ 3，每步可验证 |
| P4 | 100 道人工标注金标准评测 | 主因 Top-1 ≥ 70% 才对外显示为「结论」 |

P2 与「方法论自动打标」是同一件事的两半：诊断需要每题的方法链，方法链又只能从三种来源抽取。

## 11. 评估指标

| 指标 | 目标 |
|---|---|
| 主因 Top-1 准确率（对人工金标准） | ≥ 70%，低于则只展示「可能原因」 |
| 可诊断率（非 `UNKNOWN` 占比） | ≥ 80% |
| 证据覆盖率 | 100% |
| 过诊率（`P-SLIP` 被误归因） | ≤ 10% |
| 路径有效率（补学后 7 天同标签新题） | 正确率提升 ≥ 15pp |

## 12. 两个前置问题

1. **词表粒度不一致**：现有 20 条里「公式法」是族级，「配方法解方程」「因式分解法」是具体方法，同级混放会让对齐失真。建议拆成「求根公式」，并统一到「可直接对应一个 2–5 步骨架」的粒度。
2. **没有过程数据**：`solution` / `mark` 空表意味着现在只能做弱诊断。P0 之后要先真实跑一批上传与批改，才有对齐素材。
